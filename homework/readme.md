## Настройка окружения

Убедитесь, что у вас на компьютере установлен Python. В случае работы на Windows не рекомендуется устанавливать Python из Microsoft Store – это может привести к ошибкам при запуске тестов, поэтому лучше использовать [официальный установщик](https://www.python.org/downloads). 

Установите необходимые зависимости: `pip3 install requests PyYAML`. При работе на Windows замените здесь и далее `pip3` и `python3` на `pip` и `python` соответственно.

Также вам понадобится запускать Docker-контейнеры. Для этого надо установить [Docker Engine](https://docs.docker.com/engine/install/) или [Docker Desktop](https://docs.docker.com/desktop/) под вашу ОС.

Склонируйте репозиторий курса в папку на вашем компьютере. Далее обновляйте вашу копию репозитория с помощью `git pull` по мере размещения новых заданий и материалов. Во избежание проблем не рекомендуется менять структуру папок внутри репозитория и переносить их в другое место.

Откройте папку с репозиторием в вашей IDE и откройте файл `homework/01-guarantees/solution/guarantees.py`. Убедитесь, что IDE находит модуль `anysystem` из файла `anysystem/python/anysystem.py`. В VS Code это должно работать сразу, благодаря файлу `.env`. Для другой IDE воспользуйтесь её инструкцией по настройке окружения для Python-проектов или добавьте полный путь к папке `anysystem/python` в переменную окружения `PYTHONPATH`.

Для запуска тестов на AnySystem не требуется отдельно прописывать `PYTHONPATH` в случае, если вы будете запускать их рекомендуемым образом - из папки задания и сохраняя структуру папок репозитория.

### Регистрация

(Пропустите эту часть, если вы вольнослушатель.)

Перед тем, как сдавать задания, надо пройти регистрацию и получить токен доступа. Делается это с помощью команды:

```
python3 cli.py register
```

Введите registration token, разосланный в канале курса. Далее введите ваше полное имя (Фамилия Имя Отчество) в точности так, как оно указано в списке студентов. Если вас нет в списке студентов, зачисленных на курс, то вы не можете сдавать задания.

После успешной регистрации ваш токен доступа будет сохранен в файле `.token`. Не удаляйте этот файл. Если после регистрации вы захотите сдавать задания с другой машины, достаточно скопировать на неё этот файл.

Регистрация выполняется однократно. В случае, если файл `.token` утерян, для восстановления доступа обратитесь к преподавателям.

## Локальное тестирование решения

Перед сдачей решения в тестирующую систему обязательно проведите локальное тестирование. В каждом задании будет инструкция как это сделать.

**Пожалуйста, не пренебрегайте локальным тестированием.** Все тесты для заданий открыты, в том числе для того, чтобы вы могли быстро протестировать решение локально после каждой правки, а не отправляли его каждый раз в тестирующую систему и ждали в очереди. Тем самым вы также снизите время ожидания для товарищей, которым действительно надо зафиксировать улучшение своего решения.

Стандартный способ запуска тестов, доступный для всех заданий, это вызов следующей команды из папки задания:

```
python3 ../cli.py test --full
```

При таком способе тестирование решения производится в Docker-контейнере, в окружении аналогичном используемому в тестирующей системе.

В некоторых случаях время выполнения тестов, особенно в Docker, может зависеть от вашей системы, архитектуры процессора и т.п. Если в тестах к заданию есть лимит по времени, и при локальном тестировании ваше решение не укладывается в него, попробуйте сдать решение в систему. Возможно тесты там пройдут из-за отличий в скорости выполнения. Референсом в таких тестах служит сервер тестирующей системы. Также можно попробовать запустить тесты локально без Docker по инструкции из условия задания.

## Сдача решения

После того, как вы протестировали свое решение локально и получили лучший результат, или же приближается дедлайн, имеет смысл сдать текущее решение. Делается это из папки задания с помощью команды:

```
python3 ../cli.py submit
```

Ваше решение будет отправлено в тестирующую систему, после чего в консоль будет выводится статус вашей посылки:

- `READY` - ожидает в очереди,
- `SCHEDULED` - назначена к выполнению,
- `RUNNING` - выполняется,
- `DONE` - тестирование завершено успешно,
- `FAILED` - в ходе тестирования произошла ошибка,
- `CANCELLED` - выполнение отменено.

В случае статуса `DONE` будут выведены набранные баллы, а также путь к логу тестирования.

В случае статуса `FAILED` будет выведено сообщение об ошибке. Если вам кажется, что ошибка не связана с вашим решением, сообщите о ней преподавателям.

Все ваши посылки с их результатами сохраняются локально в папке `.submissions` внутри папки решения. Идентификатор посылки содержит время её регистрации в тестирующей системе (обычно задержка составляет несколько секунд), которое является **официальным временем сдачи решения**. Важно, чтобы это время было до дедлайна по заданию, иначе решение не будет принято.

Успешные посылки (статус `DONE`) и их результаты также сохраняются в тестирующей системе. При этом, если результат посылки оказался хуже, чем у предыдущей, то он не сохраняется. При оценивании задания берется результат **последней сохраненной посылки, сданной до дедлайна**.

### Отслеживание статуса проверки

После отправки решения скрипт продолжает работать до окончания проверки. Вы можете остановить его после вывода id посылки. Чтобы позднее проверить статус посылки используйте команду:

```
python3 ../cli.py watch
```

Данная команда найдет все незавершенные посылки и будет проверять их статус до завершения.

### Отмена проверки

Если ваша посылка очень долго находится в статусе `RUNNING`, то вы можете отменить её выполнение с помощью команды:

```
python3 ../cli.py cancel ID_ПОСЫЛКИ
```
